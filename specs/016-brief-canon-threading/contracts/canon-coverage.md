# Contract: Canon-Coverage Check

Postconditions the test suite asserts for the coverage check (FR-007 – FR-016, FR-018).

---

## C-C1 — Advisory only, never fatal

The check never raises, never fails a run, and never participates in the pre-write
validation gate. A bundle with uncovered canon is still written.

*Asserted by*: a run whose canon is entirely uncovered completes and produces a file map;
and a source-level test that the validation gate does not import or invoke the check. The
gate's own raising behaviour on schema violations is unchanged.

## C-C2 — Missing canon is reported by name

Every derived term appearing in **zero** rendered files produces a warning naming **that
term**. The report never substitutes an aggregate verdict such as "canon coverage
incomplete".

*Rationale*: a named term is actionable without opening the bundle; a verdict is noise the
operator learns to skip, which makes the check dead while still appearing alive. Naming also
degrades the failure mode of a slightly-loose extractor gracefully — a false positive is
visibly a false positive rather than an unexplained failure.

*Asserted by*: the warning text for a deliberately-uncovered term contains that term.

## C-C3 — The check fires (positive detection)

Given a rendered bundle from which canon is absent, the check **emits** a warning.

*Asserted by*: an explicit positive-detection test. Per ADR-036, a check whose tests assert
only silence cannot be distinguished from a dead check. This preserves the property
established by the advisory-path audit for every existing advisory check in this codebase —
a suite that only proves quiet-on-clean proves nothing about whether the check works.

## C-C4 — The check stays quiet on a clean bundle

Given a bundle in which every derived term appears in at least two rendered files, **no**
canon warning is emitted.

*Asserted by*: an empty warning list. C-C3 and C-C4 together are what make the check
meaningful; either alone is insufficient.

## C-C5 — Carrier locations are reported

For a covered term, the result records **which** files carry it. A term carried by exactly
one file is reported as a thin result naming that file.

*Rationale*: this is what lets a term surviving only in an artifact the operator knows is
dropped on import surface as a weak result they can judge — while the check itself encodes
no assumption about which artifacts reach a running agent, and so cannot go stale as the
platform changes.

*Asserted by*: carrier paths present in the structured result; a single-carrier term
produces a warning containing the carrier's path.

## C-C6 — All rendered files are scanned

The scan covers every file in the rendered map. No artifact kind is excluded, weighted or
privileged.

*Asserted by*: a term present only in a non-agent-reaching artifact is classified covered
(and, being single-carrier, reported as thin per C-C5).

## C-C7 — Presence, never fidelity

Warning text makes a claim about **reach** only. It must not state or imply a judgement
about whether canon survived as a usable procedure.

*Asserted by*: review of warning text against a prohibited-vocabulary list (no "correctly",
"properly", "faithfully", "accurately", or equivalent quality language).

## C-C8 — Term-oriented, not artifact-oriented

The check asks "does this term appear in any rendered file?", never "does this artifact
contain canon?". It does not iterate the skill set, does not assume every referenced
capability is generated by this tool, and carries **no exemption list**.

*Rationale*: a referenced platform-provided capability contributes no file to the rendered
map and is therefore outside the scan **structurally**, rather than by an exception entry
that would have to be maintained. This is the difference between a rule and a rule plus
exceptions.

*Asserted by*: a bundle whose agents reference platform-provided capabilities produces no
coverage failure attributable to them; and a source-level test that the check does not
reference the built-in capability set.

## C-C9 — Deterministic and offline

Repeated runs over identical input produce **identical** output, including ordering. The
check performs no model call and no network access.

*Asserted by*: repeated invocation equality, including across processes with differing hash
seeds. No builtin `hash()` is used, and no output is derived from iterating an unordered
set — set iteration order for strings is hash-seed dependent, which would pass every
single-process test while being non-reproducible in the field. Terms are ordered by first
appearance in the canon; carrier paths are sorted.

## C-C10 — Extraction is calibrated against the failing case's *shape*

Run against a committed fixture structurally equivalent to the section-11 text that produced
the observed defect — a multi-dimension rubric with named dimensions, a table with class
labels, and ordinary narrative prose alongside — extraction recovers the dimension names and
class labels, and does **not** recover the narrative prose from that same fixture.

*Rationale*: same-source negatives are what make this a calibration rather than a keyword
list, and they survive sanitisation because the discrimination lives in the *shape*, not the
vocabulary. Distinctiveness is grounded in the structure of the case that motivated the work,
not argued from first principles.

*Asserted by*: positive and negative assertions over the sanitised fixture.

**Deliberately not in this repository**: the real section-11 text. It is project canon and a
public repository is the wrong home for it, independent of how benign any individual phrase
appears. The repo holds the shapes; the operator holds the reality.

## C-C10a — Thresholds are single-constant changes

The minimum token length, maximum reported term count, and common-word list are **named
module constants**, not literals embedded in the extraction logic.

*Rationale*: final calibration happens outside this repository — the operator runs the
extractor against the real section 11 during their validation pass and reports whether it
caught the right terms and left the prose alone. That feedback must land as a one-constant
change with the reasoning recorded beside it, not a refactor.

*Asserted by*: the constants are importable and independently overridable in tests.

## C-C11 — Canon-unique scope

A phrase appearing in the brief's other fields as well as section 11 is not a derived term.

*Rationale*: the defect concerns material whose only carrier is section 11. A phrase carried
by another brief field reaches the generators by an existing path, so its coverage says
nothing about this defect and its presence in the report is pure noise. Scoping the check to
canon-unique material makes the signal exactly as narrow as the failure it guards.

*Asserted by*: a phrase seeded into both section 11 and another brief field produces no
warning even when absent from the bundle.
